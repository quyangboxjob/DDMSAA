# DDMSAA フロントエンド開発規約

## 1. 技術

React + TypeScript + Vite を使用する。API の真実は `docs/基本設計/共通/spec-07-api-list.yaml`、画面権限の真実は `spec-03-auth-ui.md` とする。

## 2. ロール

§§§ts
type Role = "ADMIN" | "EMPLOYEE" | "CUSTOMER";
§§§

画面の表示制御は操作性のために実装するが、最終的な認可は API が行う。CUSTOMER に作成/更新/取消し/承認/アップロード/CSV のボタンを表示しない。EMPLOYEE は担当顧客だけを選択できるようにする。

## 3. フォーム

- 必須、文字数、数値範囲、日付範囲をクライアントでも検証し、API の 422 フィールドエラーを項目横に表示する。
- 注文の小計、税額、合計はプレビューとして表示してよいが、確定値はサーバー応答で置き換える。
- 更新時は `version` を送信し、409 では再読み込みを促す。
- パスワード、セッション Cookie、生の添付 URL を状態管理やログに保持しない。

## 4. 添付・出力

- 添付の PENDING/REJECTED をダウンロード可能として表示しない。
- SAFE でも API のダウンロード URL を使い、ストレージ URL を画面へ埋め込まない。
- 非同期出力は export job の状態をポーリングし、READY、FAILED、EXPIRED を表示する。

## 5. テスト

- ロール別のメニューと操作非表示。
- 担当外顧客、他社注文、添付非公開の画面遷移。
- 注文税額表示、承認/差戻し、409、422、CSV 非同期状態。
