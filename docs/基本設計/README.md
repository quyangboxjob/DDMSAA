> 再利用可能な「基本設計」フェーズの文書テンプレート集。**新規プロジェクトではディレクトリごと複製**し、各ファイル内の「記入要領」に従ってプレースホルダを置換する。

## 1. 開発プロセスにおける位置づけ

```
①要件定義 → ②基本設計 → ③詳細設計 → ④実装 → ⑤テスト → ⑥リリース・運用
            ↑ 本テンプレートの対象範囲
```

- **基本設計（外部設計）**：ユーザ・外部の視点に立ち、システムが「外部に対して何を行い、どう見えるか」を定義する。
- 上流の入力：要件定義書（ロール権限、論理データモデル、技術スタックなど）。
- 下流の成果物：詳細設計・実装の根拠となるもの（権限、DB、API、基盤設計など）。

> データ層の標準（項目定義、列挙コード値、DB 命名、型）は `開発規約/` 配下の開発規約で管理する。本テンプレートの DB 設計は当該規約に従い、ここでは重複して定義しない。

## 2. ディレクトリ構成

基本設計は次の 3 ディレクトリで構成する。

```
基本設計/
├── 共通/          システム全体で唯一の文書（SSOT）
├── 基盤/          バックエンド基盤の設計
└── データベース/  DB 接続・構築・移行の設計
```

> **配置の原則**：システム全体で唯一であり、複数の箇所から参照され、単一情報源（SSOT）を保つ必要があるものは `共通/` に置く。技術スタック固有の基盤設計は `基盤/`、DB 製品固有の設計は `データベース/` に置く。

### 作成順序

番号はファイルの識別用であり、**作成順序とは一致しない**。次の順序で進める（矢印は依存関係）。

1. `01 構成`：技術的前提を固める。
2. `03 権限`：機能・DB・API・画面の共通前提（ロール R-）のため、早期に確定する。列挙コード値は `開発規約/` の T07 で先に定義する。
3. `04 業務フロー` → `02 機能一覧`：業務の流れから機能を洗い出し、要件との対応を確定する（04 と 02 は往復して作成してよい）。
4. `06 DB` → `07 API` → `08 外部インタフェース` → `09 メッセージ`。
5. `05 画面一覧` → `10 画面遷移図` → `12 画面共通` → `16 画面設計`。
6. `14 帳票` / `15 バッチ`。
7. `11 非機能` → `17 データ移行` / `18 運用`。

```
01 アーキテクチャ
 ├─ 03 権限 ─┐ 共通前提（列挙コード値は 規約 T07 を参照）
 │          ▼
 ├─ 04 業務フロー ─→ 02 機能一覧 ─┬─ 05 画面一覧 ─→ 10 画面遷移図 ─→ 12 画面共通 ─→ 16 画面設計
 │                              └─ 14 帳票 / 15 バッチ
 ├─ 06 DB ─→ 07 API ─→ 08 外部インタフェース ─→ 09 メッセージ
 └─ 11 非機能 ─→ 17 データ移行 / 18 運用
```
