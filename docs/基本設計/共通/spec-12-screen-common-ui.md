# 12 画面共通設計（共通UI方針）

> **全画面で共通の** UI 標準と方針を定義する：共通レイアウト・コンポーネント、メッセージ表示、入力チェック表示、画面状態、表示形式、ロール別表示、ダウンロード UX、状態色、レスポンシブ・ブラウザ・アクセシビリティ。
> **帰属：システム全体で唯一 → `共通/`**（ゴールデンルール）。各画面設計は**本方針に従い、重複定義しない**。
> 本方針は「どう表示し、どう操作させるかの統一ルール」のみを定め、個別画面は描かない（個別画面は各画面設計を参照）。

（文書ヘッダは `spec-00-doc-standard-ui.md` を参照）

---

## 1. 画面全体構成・共通レイアウト

> ASCII または Figma リンクを貼る。ヘッダ/ナビゲーション/コンテンツ領域/フッタの固定構造を定義する。

```
┌────────────────────────────────────────────┐
│ [Logo] 〇〇システム        [ユーザ名▼] [ログアウト] │  ← 共通ヘッダ（固定）
├────────────┬───────────────────────────────┤
│ ナビメニュー │  パンくず: ホーム > 〇〇          │
│ （ロール別） ├───────────────────────────────┤
│  · 〇〇     │                               │
│  · 〇〇     │   コンテンツ領域（各画面）        │
│            │                               │
│            │   ※メッセージ領域（toast/行内）  │
├────────────┴───────────────────────────────┤
│ フッタ: © 〇〇 / バージョン                    │  ← 共通フッタ
└────────────────────────────────────────────┘
```

| 項目 | 方針 |
|------|------|
| レイアウトグリッド | 〇〇（例：12 カラムグリッド / 固定幅 + 可変コンテンツ領域） |
| ヘッダ | 全画面で固定：システム名・ログインユーザ・ログアウト。認証系画面（ログイン/認証）ではナビゲーションを表示しない |
| ナビゲーションメニュー | **ロールごとに**異なるメニュー項目を表示する（§7 / `spec-03-auth-ui.md` を参照） |
| パンくず | コンテンツ領域の上部に現在位置を表示する |

## 2. 共通コンポーネント一覧

> コンポーネントの**外観と操作の統一標準**（実装方法は詳細設計/`spec-frontend-coding-rule.md` を参照。ここでは外観と挙動のみを定める）。

| コンポーネント | 統一方針 |
|------|---------|
| ボタン | 主操作/副操作/危険操作（例：削除・停止）でスタイルを区別する。危険操作は必ず確認ダイアログ（§3）を経由する |
| テーブル | 列見出し・ソート・ページング・空状態を統一する。行クリックで詳細へ進む操作も統一する |
| ページング | 1ページあたりの件数・ページ番号のスタイルを統一する（デフォルト 〇〇 件/ページ） |
| フォーム | ラベル位置・必須マーク（例：`*`）・エラー表示位置を統一する（§4） |
| モーダル/ダイアログ | 確認・フォームポップアップの統一スタイルと閉じる挙動 |
| 検索・フィルタ領域 | 位置・リセット・検索ボタンの統一レイアウト |

## 3. メッセージ表示方針（`spec-09-message-list` を参照し、文言は再記載しない）

> バックエンドは `messageId`(+`messageArgs`) のみを返し、フロントエンドが `spec-09-message-list.yaml` に従って文言を解決して表示する。**文言のハードコードは禁止**。

| 区分 | messageId プレフィックス | 表示方式 | 説明 |
|------|:-----:|---------|------|
| 情報 INFO | `I` | Toast（自動消去） | 操作成功など（例：`I0003` ログイン成功） |
| 警告/確認 WARNING | `W` | **確認ダイアログ**（OK/キャンセル）またはハイライト | 削除・停止・取消など不可逆な操作の前に確認する（例：`W0010` 削除確認） |
| エラー ERROR | `E` | 行内（項目単位）/ Toast / ダイアログ | 入力チェックエラーは該当箇所の近くに表示し、システムエラーはダイアログを用いる |

| 項目 | 方針 |
|------|------|
| 確認ダイアログ | 危険/不可逆な操作（削除・停止・変更の確定・取消）は実行前に必ず表示する（W 区分の messageId に対応） |
| messageArgs | `{0},{1}` のプレースホルダに従って置換する（例：`I0010` の登録 ID） |
| Toast 表示時間 | 〇〇 秒。手動で閉じることも可能 |

## 4. 入力・チェック表示方針

> クライアント側のチェックは**バックエンドと整合させる**（操作性のためのものであり、バックエンドの代替ではない。`spec-frontend-coding-rule.md` を参照）。

| 項目 | 方針 |
|------|------|
| 必須マーク | ラベルの後に `*` または統一スタイル |
| チェックタイミング | 〇〇（フォーカス喪失時 / 送信時 / 両方） |
| エラー表示 | 項目の下に行内でエラー文言を表示（messageId で解決。例：`E0030`） |
| 送信制御 | チェック未通過時は送信を無効化 or 送信後にフォーム全体へフィードバック |

## 5. 画面状態の標準

> 各画面は以下の状態について統一した表現を持つこと。「正常時」だけを描いてはならない。

| 状態 | 統一表現 |
|------|---------|
| 読込中 | Loading 表示（スケルトン / Spinner のいずれかに統一） |
| エラー | エラー表示 + 再試行の導線（messageId で解決） |
| データなし | 空状態のプレースホルダ文言（例：「該当データなし」） |
| 権限なし | 入口を表示しない（§7）。権限外アクセスは統一的に遷移/通知する |

## 6. 表示形式方針

> データを「ユーザにどう見せるか」の統一ルール（保存/伝送形式は `06`/`07`/`データ辞書` を参照）。

<!-- rule: time.display-common-util -->
| 種類 | 表示形式 | 説明 |
|------|---------|------|
| 日付 | `YYYY-MM-DD`（または `YYYY年MM月DD日`。いずれかに統一） | |
| 日時/タイムゾーン | **バックエンドの `+09:00` 付き ISO 8601 文字列 → 表示層の共通ユーティリティで統一書式化** | **各コンポーネント内での独自のタイムゾーン変換は禁止**。共通ユーティリティ関数を用いる |
| 数値/件数 | 桁区切り 〇〇 | |
| 金額 | 〇〇（本システムに金額がなければ削除） | |
| 列挙 | バックエンドが文字列コード（例：`ACTIVE`）を返す → フロントエンドが統一マッピングで**日本語名**（例：「在職中」）を表示する。JOIN はしない | マッピング元は `07 API` の列挙/データ辞書 T07 と整合させる |
| マスク項目 | 証明書番号・口座などの機密項目はサーバ側でマスク済み（`****4567`）。フロントエンドはそのまま表示する | |

## 7. ロール別表示制御方針（`spec-03-auth-ui` を参照）

| 項目 | 方針 |
|------|------|
| 原則 | **表示制御 ≠ セキュリティ制御**：非表示は操作性のためのみであり、データ範囲/項目権限はバックエンドで強制する（詳細項目はサーバ側で権限に応じて null にし、フロントエンドは null かどうかで描画する） |
| メニュー/ボタン | ロール（〇〇 / 〇〇 / 〇〇）に応じて表示または非表示にする（例：「新規登録」は管理者のみ） |
| 認証後の遷移 | ロール別の既定ランディングページ（例：管理者/マネージャ→ダッシュボード SCR-10、ユーザ→個人情報 SCR-08） |
| 項目 | 項目参照マトリクスに従って表示する（`spec-03-auth-ui` §3） |

## 8. ファイルダウンロード UX

| 項目 | 方針 |
|------|------|
| ダウンロード方式 | クリック→バックエンドで生成→ブラウザでダウンロード。進捗/完了を通知する |
| 単一/複数ファイル | 単数＝直接ダウンロード、複数＝ZIP（例：確認票） |
| ファイル命名 | `07 API` / 帳票設計と一致させる（例：`〇〇_YYYYMMDD.xlsx`） |
| 失敗時の処理 | 失敗時は messageId を表示し、無言で終わらせない |

## 9. 状態色・強調表示

| 用途 | 方針 |
|------|------|
| 状態色 | 各状態（例：申請の 確認待ち/処理中/承認/却下）の統一配色 |
| 強調/ハイライト | 〇〇（例：期限超過データのハイライト、超過日数の表示。対応する W 区分の messageId を `spec-09-message-list.yaml` に採番する） |
| 危険操作 | 統一した警告色 |
