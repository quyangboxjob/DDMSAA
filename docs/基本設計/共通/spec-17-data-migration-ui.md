# 17 データ移行設計

> 現行システム（または Excel・紙台帳など）から本システムへ**業務データを移行する方針・範囲・対応付け・切替手順**を定義する。非機能要件 `spec-11-non-functional-ui.md` §4「移行」の要求を具体化する。
> **帰属：システム全体で唯一 → `共通/`**。移行データの投入**機構**（Flyway `V1` 初期移行データ）は `データベース/spec-db-migration-ui.md` を正とし、本書では再定義しない。本書は「何を・どこから・どう変換して・いつ切り替えるか」を定める。
> 現行システムが存在せず移行対象がない場合は、§1 に「移行なし」と記載し、以降の節を削除してよい。

（文書ヘッダは `spec-00-doc-standard-ui.md` を参照）

## 4. 移行検証

| 検証観点 | 方法 | 合格基準 |
|------|------|------|
| 件数 | 移行元件数 = 移行先件数 + 除外件数 | 差異 0 件 |
| 金額・数量の合計 | 移行元と移行先で集計値を突合 | 一致 |
| 抜き取り確認 | 〇〇 件を画面で目視確認 | 不備 0 件 |
| 業務確認 | 利用部門が主要業務を移行データで実施 | 業務担当者の承認 |
