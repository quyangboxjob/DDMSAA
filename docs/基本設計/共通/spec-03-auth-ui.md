# 03 権限設計

> ロール定義、操作権限マトリクス、項目単位の参照権限マトリクス、データ範囲（行単位）ルールを定める。ロールの種類・名称・権限範囲はプロジェクトで定義する（プロジェクト固有の規約）。本書の ADMIN / MANAGER / USER とマトリクスの内容はすべて記入例であり、プロジェクトのロール定義に置き換える。
> 本システムは権限の粒度が細かい（ロール×操作、ロール×項目、自部門/本人）ため、散逸を避けて独立した文書とする。

（文書ヘッダは `spec-00-doc-standard-ui.md` を参照）

## 1. ロール定義

> ロールはプロジェクトで定義する。下表は記入例。

| ロールID | ロール名 | 対象者 | 説明 |
|--------|--------|-------|------|
| R-ADMIN | 管理者 | 管理部門所属のユーザ | 全権限 |
| R-MANAGER | マネージャ | 各部門の管理者 | 自部門の範囲 |
| R-USER | 一般ユーザ | 上記以外の全ユーザ | 本人のみ |

|------|:----:|:------:|:----:|---------|
| ユーザ登録 | ○ | × | × | |
| ユーザ情報編集 | ○ | × | ○ | ユーザは本人のみ |

| システムロック設定・解除 | ○ | ○ | × | マネージャは自部門に限る |
| 申請承認（承認・却下） | ○ | × | × | |
| 帳票出力 | ○ | × | ○ | ユーザは本人分のみ |

## 3. 項目単位の参照権限マトリクス（他者の情報を参照する場合）

> 要件のデータ参照権限を受けたもの。○=表示可、×=表示不可。

| 項目 | 管理者 | マネージャ(自部門) | ユーザ(他者) |
|------|:----:|:--------------:|:----------:|
| ユーザID・氏名・部門・ユーザ種別・役職・ステータス・業務用メール | ○ | ○ | ○ |
| 住所・電話（勤務先/個人） | ○ | ○ | × |
| 個人メール | ○ | × | × |
| 扶養家族数 | ○ | ○ | × |
| 口座番号・個人番号・年金保険番号 | ○ | × | × |
| {{ … }} | | | |

> 本人情報の参照：全項目表示可。ただし口座番号・個人番号・年金保険番号の**編集**は申請制とする（詳細は変更申請を参照）。

## 4. データ範囲（行単位の権限）

> ロールごとのデータ範囲はプロジェクトで定義する。下表は記入例。

| ロール | アクセス可能なデータ範囲 | 実装上のポイント |
|------|--------------|---------|
| 管理者 | 全ユーザ | 制限なし |
| マネージャ | 自部門のユーザ | department_id で絞り込み |
| ユーザ | 本人のみ | user_id で絞り込み |

## 5. 権限判定ルール・特記事項

<!-- rule: auth.three-layer-permission -->
- 権限 = **操作権限（機能単位）** ∩ **データ範囲（行単位）** ∩ **項目参照（列単位）** の三層を重ねて判定する。
- ロック状態・理由は本人には**非表示**とする。
- マネージャがロック操作を行った場合は管理者へ通知する（`spec-08-external-interface-ui` を参照）。
- {{ プロジェクト固有ルールを補足 }}

### 記入要領

- 項目マトリクスは `spec-06-db-physical` の項目に対応する。行単位の範囲は API 実装時に反映する（`spec-07-api-list` を参照）。
- 「範囲備考」には必ず「自部門/本人」を明記すること。記載がないと、実装時に行単位の絞り込みが漏れやすい。
