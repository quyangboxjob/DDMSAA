# 03 権限設計

> ロール定義、操作権限マトリクス、項目単位の参照権限マトリクス、データ範囲（行単位）ルールを定める。DDMSAA のロールは ADMIN / EMPLOYEE / CUSTOMER の 3 種（`要件定義/requirements.md` §2）。
> 本システムは権限の粒度が細かい（ロール×操作、ロール×項目、担当顧客/自社）ため、散逸を避けて独立した文書とする。

（文書ヘッダは `spec-00-doc-standard-ui.md` を参照）

## 1. ロール定義

| ロールID | ロール名 | DB 値（`users.role`） | 対象者 | 説明 | ユーザ ID の prefix |
|--------|--------|:---:|-------|------|:---:|
| R-ADMIN | 管理者 | 1 | システム管理者 | 全顧客・全注文。マスタ・利用者・承認経路・監査・帳票を管理し、承認を行う | A |
| R-EMPLOYEE | 営業担当 | 2 | 営業・事務担当 | `customer_assignments` で有効な担当顧客の注文を登録・更新・申請する | E |
| R-CUSTOMER | 顧客 | 3 | 顧客企業の閲覧アカウント | 自社（`users.customer_id`）の注文・承認結果・公開済み添付・PDF を参照する | C |

- 認証はユーザ ID + Magic Link（`基盤/spec-02-auth-service-ui.md`）。JWT の `role` claim はロール名の文字列（ADMIN / EMPLOYEE / CUSTOMER）、`sub` はユーザ ID。
- `role` が NULL・不正値の場合は、最も権限の小さい `CUSTOMER` として扱い、かつ `customer_id` がなければ全データ範囲を空とする。
- ロールの値域は T07-1（`開発規約/spec-data-dictionary-project-temp.md`）を正とする。

## 4. データ範囲（行単位の権限）

| ロール | 範囲 | 実現方式 |
|------|------|------|
| 管理者 | 全件 | 条件なし |
| 営業担当 | 有効な担当割当（`customer_assignments.is_active = TRUE`）がある顧客と、その注文・添付・集計・出力 | Service が JWT の `sub` から担当顧客 ID 集合を求め、SQL の条件に必ず付与する |
| 顧客 | 自社（`users.customer_id`）の顧客情報・注文、公開かつ SAFE の添付 | Service が `users.customer_id` を求め、SQL の条件に必ず付与する |

- 範囲の判定はフロントエンドに依存しない。URL やリクエスト値で他の顧客・注文を指定しても、範囲外の 1 件は **404**（存在を開示しない）を返し、一覧・検索では範囲外を自動的に除外する。ロール自体が不足する操作は **403**（BR-AUTH-006）。
- 担当割当を外した場合、その顧客の既存注文も営業担当の範囲から外れる（作成者であっても参照不可）。

## 5. 権限判定ルール・特記事項

1. API Gateway が JWT（署名・有効期限・発行者）を検証し、`business-service-core` は `@PreAuthorize` でロールを、Service 層でデータ範囲・状態を判定する（`基盤/spec-00-architecture-ui.md`）。
2. **停用・ロックの反映**：停用・ロックは新たなログイン（Magic Link の要求・検証）を止める。発行済みの JWT は有効期限（最長 60 分）まで利用でき、期限切れ後は再ログインできない。業務 API はリクエストごとの状態照会を行わない（JWT の検証のみ）。最長 60 分の遅延は要件上許容する（2026-10-20 決定）。
3. 承認・差戻しは、有効な ADMIN のうち申請者（`approval_requests.created_by`）以外が実行でき、実行者を `approver_user_id` に記録する。申請者本人は 409（`E0056`）（BR-APR-002）。
4. 添付・PDF・CSV のダウンロードは毎回、注文・顧客・公開範囲・スキャン状態・ジョブ依頼者を再検証する。ストレージの URL は返さない。
5. ログイン（Magic Link の要求・検証。auth-service が INSERT）、権限拒否（403 と範囲外 1 件の 404）、状態変更、添付のアップロード・ダウンロード・削除、PDF・CSV の出力は `audit_logs` に記録する。操作名の一覧は `spec-08-business-rule-list.md` BR-AUD-001 を正とする。
6. Magic Link 要求の応答は、利用者の存在・停用・ロックに関わらず同一（`I0001`）とする。パスワードがないため、試行回数によるロックアウトは行わない（ロックは ADMIN が `system_locks` で行う）。
