# 09 共通メッセージ一覧

<!-- rule: msg.no-hardcoded-text -->
> エラー・確認・通知・完了などのメッセージ文言を集中管理する。表現の統一、再利用、多言語の外部化を容易にする。
> 画面・API は **messageId** で参照し、各所に文言をハードコードしない。
> **機械可読の SSOT = `spec-09-message-list.yaml`**（全 messageId と文言を含む）。本 md は仕組みのみを説明し、メッセージ明細を重複記載しない（二重管理による乖離を避ける）。

（文書ヘッダは `spec-00-doc-standard-ui.md` を参照）

---

## 1. messageId 命名規則

<!-- rule: msg.id-format -->
- **形式**：`[IWE]NNNN`（区分プレフィックス 1 文字 + 4 桁連番、**ハイフンなし**）。例：`I0010`、`W0010`、`E0020`。
<!-- rule: msg.category-iwe-no-c -->
- **区分**：**I**=INFO（通知・成功）、**W**=WARNING（注意・**確認ダイアログ**）、**E**=ERROR（エラー）。**C 区分は設けない**（確認は W に含める）。
- **文言の正本**：メッセージ一覧（`spec-09-message-list.yaml`、多言語対応時は `.zh/.en` が翻訳）とする。
<!-- rule: msg.id-must-exist-in-catalog -->
- **存在要件**：コード・画面・テストで使用する messageId は、すべて上記の正本に存在しなければならない。存在しない場合は先に正本へ登録してから使用する。

<!-- rule: msg.number-bands -->
### 番号帯（共通メッセージ）

| 範囲 | 用途 |
|------|------|
| `E0001`〜`E0013` | 認証・認可・ロック（429）・未存在・業務異常・入力検証・ファイル・システム共通 |
| `E0020` | ログイン不可 |
| `E0030`〜`E0034` | クライアント側入力チェック（必須・形式・長さ・範囲） |
| `E0040`〜`E0043` | API Gateway（Token 欠落/不正・ルート未一致・タイムアウト） |
| `I0001` / `I0003` / `I0010`〜`I0012` | 認証メール送信・ログイン・登録/更新/削除の完了通知 |
| `W0010` / `W0011` | 削除確認・入力破棄確認 |
| `I0020`〜`I0031` / `W0020`〜`W0026` / `E0050` | 画面業務メッセージ（承認・取消し・添付・出力・無効化確認など。画面設計で採番） |

> 上記は基盤・規約・各 SSOT が参照する共通メッセージ。業務固有のメッセージは上記以外の空き番号で `spec-09-message-list.yaml`（および zh/en）へ追記する。

## 2. メッセージカタログ（多言語）

メッセージ文言の唯一の出典は、言語別ディレクトリの yaml とする：

| 言語 | ファイル | 説明 |
|------|------|------|
| 日本語（正本） | `spec-09-message-list.yaml` | ja 正本。messageId と category の正式な出典 |
| 中国語 | `spec-09-message-list.zh.yaml` | 翻訳（messageId/category は正本と同一） |
| English | `spec-09-message-list.en.yaml` | 翻訳 |

- messageId と category は**全言語共通**で、message の文言のみが言語ごとに異なる。デフォルト言語＝日本語。
- 動的な値は `{0},{1}` のプレースホルダで表し、バックエンドが `messageArgs` で渡す。
- 実行時、フロントエンドは i18n（react-i18next）により現在の言語に応じて解決・表示する（`spec-12-screen-common-ui.md` §3 を参照）。

## 3. HTTP ステータスと messageId の関係

- **messageId は唯一の識別・表示キー**である。HTTP ステータスは例外種別で決まり、messageId とは独立する（固定セットは `spec-07-api-list.yaml`/`.md` §1 を参照）。
- 同一の messageId は常に同一の文言に対応する。

### 記入要領

- メッセージの追加/変更は一律 `spec-09-message-list.yaml`（および zh/en の翻訳）で行い、本 md ではメッセージ明細を管理しない。
- messageId は画面（`spec-12-screen-common-ui` / 各画面設計）および API（`spec-07-api-list`）から参照される。
- 同一の事象（例：「ログインできない」）には必ず同じ messageId を再利用し、表現の一貫性を保つ。
