# 基盤基本設計 — 認証サービス

## 1. 認証フロー

1. 利用者が `POST /api/auth/login` に `loginId` と `password` を送信する。
2. サーバーは有効な利用者を取得し、`password_hash` を BCrypt で照合する。
3. 成功時は十分な乱数のセッション値を生成し、ハッシュだけを `user_sessions` に保存する。
4. 生の値は `DDMSAA_SESSION` Cookie にだけ設定し、`GET /api/auth/me` で利用者情報を返す。
5. ログアウト、失効、無効化、期限切れではセッションを revoke する。

## 2. 失敗とロック

| 条件 | 処理 |
|---|---|
| ログイン ID 不明、パスワード不一致、無効利用者 | 同一の `401` 応答。存在理由を返さない |
| 5 回連続失敗 | `locked_until` を 30 分後に設定し、以後 `423` |
| 成功ログイン | 失敗回数を 0 に戻す |
| Cookie 不正・失効 | `401`、再ログインを要求 |
| CSRF 不正 | `403` |

## 3. ロール

`ADMIN`、`EMPLOYEE`、`CUSTOMER` の 3 種を `users.role_code` に文字列で保存する。データ範囲は [共通認証設計](../共通/spec-03-auth-ui.md) の定義に従う。

## 4. 非採用

メールリンク認証、認証メール、SMS 認証、平文パスワード、クライアント保存の長期トークン、JWT refresh token は初版で使用しない。
