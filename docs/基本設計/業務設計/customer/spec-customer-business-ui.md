## 2. 目的・範囲

顧客マスタ、顧客の連絡先、顧客担当者および顧客利用者との所属関係を管理する。顧客は自社情報を参照できるが、重要情報の変更は管理者が行う。

## 3. 関連画面一覧

| 画面 ID | 画面名 | 主な利用者 | 主な機能 |
| --- | --- | --- | --- |
| SCR-CUS-01 | 顧客一覧 | 管理者、担当社員 | 顧客コード・名称・有効状態で検索する。担当社員は割当済み顧客のみ。 |
| SCR-CUS-02 | 顧客詳細 | 管理者、担当社員、当該顧客 | 基本情報、連絡先、関連注文を参照する。担当社員は割当済み顧客、顧客は自社のみ。 |
| SCR-CUS-03 | 顧客登録・編集 | 管理者 | 顧客情報、担当社員、有効状態を登録・更新する。 |

## 4. 業務ルール

- 顧客コードは一意とし、登録後の変更は原則不可とする。
- 無効顧客は新規注文の対象に選択できない。ただし過去注文の参照は可能とする。
- 顧客役割の利用者は自社顧客だけを参照でき、顧客マスタの編集はできない。
- 一般社員は `employee_customer_assignments` に登録された顧客だけを参照できる。未割当顧客の一覧・詳細は返さない。
- 物理削除は行わず、有効状態で利用停止を表現する。
- 顧客の住所、連絡先、担当者の変更は監査ログに記録する。

## 5. 主なデータ

| エンティティ | 主な項目 | 制約 |
| --- | --- | --- |
| customers | customer_id, customer_code, customer_name, address, phone, email, status | customer_code は一意、status は active/inactive。 |
| customer_contacts | contact_id, customer_id, name, department, email, phone | 顧客に 0 件以上の担当者を持てる。 |
| employee_customer_assignments | user_id, customer_id | 一般社員の担当範囲を管理する。 |

## 6. API 概要

| メソッド | パス | 権限 | 内容 |
| --- | --- | --- | --- |
| GET | `/api/customers` | 管理者、担当社員 | 担当社員には割当済み顧客だけを返す。 |
| POST | `/api/customers` | 管理者 | 顧客を登録する。 |
| GET | `/api/customers/{customerId}` | 管理者、担当社員、当該顧客 | 顧客詳細を取得する。 |
| PATCH | `/api/customers/{customerId}` | 管理者 | 顧客情報を更新する。 |
| PATCH | `/api/customers/{customerId}/status` | 管理者 | 有効/無効を変更する。 |
