## 2. 目的・範囲

見積書、注文書、仕様書など、注文に紐付く添付ファイルを管理する。管理者および一般社員だけがアップロード・削除でき、顧客は自社注文に紐付く閲覧可能なファイルをダウンロードするだけとする。

## 3. 関連画面一覧

| 画面 ID | 画面名 | 主な利用者 | 主な機能 |
| --- | --- | --- | --- |
| SCR-FIL-01 | 添付ファイル一覧 | 権限保有者 | 注文詳細内で添付の一覧、種別、登録者、登録日時を表示する。 |
| SCR-FIL-02 | 添付アップロード | 管理者、一般社員 | 許可形式・サイズを検証して注文にファイルを添付する。 |
| SCR-FIL-03 | 添付ダウンロード | 権限保有者 | 認可判定後にダウンロードを開始する。 |

## 4. 業務ルール

- 添付は必ず 1 件の注文に紐付ける。注文が存在しない添付を作成しない。
- 顧客はアップロード、置換、削除をできない。自社注文に紐付く「顧客閲覧可」の添付だけをダウンロードできる。
- ダウンロードはファイル保存先を直接公開せず、認可済み API を経由する。
- 実行形式など禁止拡張子を拒否する。許可拡張子・最大サイズ・ウイルススキャンは未確定事項として運用設計で決める。
- ファイル登録・削除・ダウンロードを監査ログに記録する。削除は物理削除ではなく削除状態を記録する方針を基本とする。

## 5. 主なデータ

| エンティティ | 主な項目 | 制約 |
| --- | --- | --- |
| order_attachments | attachment_id, order_id, original_file_name, storage_key, content_type, size_bytes, visibility, uploaded_by, uploaded_at, deleted_at | order_id 必須。storage_key は一意。 |
| attachment_access_logs | attachment_id, actor_user_id, action, occurred_at, result | ダウンロード可否と操作を記録する。 |

`visibility` は初稿では `INTERNAL`（管理者・一般社員のみ）と `CUSTOMER`（当該顧客も閲覧可）の 2 値とする。

## 6. API 概要

| メソッド | パス | 権限 | 内容 |
| --- | --- | --- | --- |
| GET | `/api/orders/{orderId}/attachments` | 権限保有者 | 権限で絞り込んだ添付一覧を取得する。 |
| POST | `/api/orders/{orderId}/attachments` | 管理者、一般社員 | 添付をアップロードする。 |
| GET | `/api/attachments/{attachmentId}/download` | 権限保有者 | 認可後にストリームまたは期限付き URL を返す。 |
| DELETE | `/api/attachments/{attachmentId}` | 管理者、登録者 | 添付を論理削除する。 |

## 7. 未確定事項
