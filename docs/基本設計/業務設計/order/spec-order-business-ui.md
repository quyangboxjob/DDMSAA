# 業務基本設計 — 注文管理

## 1. 目的と利用者

ADMIN は全注文を、EMPLOYEE は担当顧客の注文を作成・編集・申請・取消しできる。CUSTOMER は自社注文を閲覧するだけである。

## 2. 画面

| 画面 | 主な利用者 | 内容 |
|---|---|---|
| 注文一覧 | 全ロール | データ範囲に限定した検索・状態表示 |
| 注文登録/編集 | ADMIN/EMPLOYEE | 顧客、明細、数量、単価、添付、申請 |
| 注文詳細 | 全ロール | 金額、税、状態履歴、承認履歴、許可済み添付 |
| 注文取消し | ADMIN/EMPLOYEE | 理由入力、取消し後の通知 |

## 3. 状態・権限

| 状態 | 編集 | 申請 | 取消し |
|---|---|---|---|
| DRAFT | ADMIN/担当EMPLOYEE | ○ | ○ |
| RETURNED | ADMIN/担当EMPLOYEE | ○ | ○ |
| PENDING_APPROVAL | × | × | × |
| APPROVED | × | × | ADMIN のみ |
| CANCELLED | × | × | × |

## 4. 金額

- 明細は商品を選択した時点のコード、名称、単価、税区分、税率を保存する。
- 明細金額は `quantity × unit_price`、税額は `HALF_UP(line_amount × tax_rate / 100)` とする。
- 税区分は STANDARD 10%、REDUCED 8%、EXEMPT 0%。値引き、送料、外貨は初版で扱わない。
- サーバーが明細から小計、税額、合計を再計算し、画面からの集計値は信用しない。

## 5. 訂正と監査

承認済み注文は直接変更しない。取消し後、新規注文を作成して訂正する場合は `revised_from_order_id` に元注文を記録できる。作成、更新、申請、取消し、状態遷移、競合は監査ログと状態履歴に残す。
