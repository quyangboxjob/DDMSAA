## 2. 目的・範囲

一般社員が顧客に代わって注文を作成し、明細・金額・状態を管理する。顧客は自社注文を閲覧できるが、登録、更新、取消および添付登録は行えない。

## 3. 状態遷移

```text
下書き → 承認待ち → 承認済み
  ↑         ↓
  └── 差戻し

下書き / 差戻し → 取消
```

| 状態 | 意味 | 許可操作 |
| --- | --- | --- |
| 下書き | 作成途中 | 作成者が編集、削除、添付、承認依頼できる。 |
| 承認待ち | 承認者の判断待ち | 承認者が承認または理由付き差戻しできる。 |
| 差戻し | 修正待ち | 作成者が修正し、再承認依頼できる。 |
| 承認済み | 有効な注文 | 参照、帳票出力。直接更新は不可。 |
| 取消 | 取消済み | 参照のみ。取消理由と実行者を残す。 |

## 4. 関連画面一覧

| 画面 ID | 画面名 | 主な利用者 | 主な機能 |
| --- | --- | --- | --- |
| SCR-ORD-01 | 注文一覧 | 管理者、担当社員、顧客 | 注文番号、顧客、日付、状態、金額で検索する。担当社員は自分の注文、顧客は自社分のみ。 |
| SCR-ORD-02 | 注文詳細 | 管理者、担当社員、顧客 | ヘッダ、明細、承認履歴、添付を表示する。担当社員は自分の注文、顧客は自社分のみ。 |
| SCR-ORD-03 | 注文登録・編集 | 管理者、担当社員 | 顧客・商品明細を入力し、下書き保存・承認依頼を行う。担当社員は割当済み顧客だけを選択できる。 |
| SCR-ORD-04 | 取消確認 | 管理者、作成者 | 下書きまたは差戻し注文を理由付きで取消する。 |

## 5. 業務ルール

- 注文番号はサーバーが一意に採番する。採番形式は未確定のため、初稿では `ORD-YYYYMMDD-連番` を候補とする。
- 注文は有効な顧客および有効な商品を少なくとも 1 明細持たなければ承認依頼できない。
- 明細金額は数量 × 単価、注文金額は明細合計と税額の合計で計算する。税計算・端数処理・値引き・送料は未確定事項とする。
- 注文作成時の顧客名、商品名、単価、税区分はスナップショットとして明細に保持する。
- 承認済み注文を変更する場合は直接更新せず、差戻しまたは改訂注文として履歴を残す。改訂方式は詳細設計で決定する。
- 顧客向け API は必ず所属顧客 ID を条件に加え、他社の注文を返さない。
- 一般社員向け API は、一覧・詳細・更新・取消・承認依頼のいずれも `sales_user_id` が本人の注文だけを対象とする。注文登録時は、選択した顧客が `employee_customer_assignments` に割り当てられていることを検証する。

## 6. 主なデータ

| エンティティ | 主な項目 | 制約 |
| --- | --- | --- |
| orders | order_id, order_number, customer_id, sales_user_id, order_date, status, subtotal, tax_amount, total_amount, version | order_number は一意。status は状態遷移に従う。 |
| order_items | order_item_id, order_id, line_no, product_id, product_name_snapshot, quantity, unit_price, tax_category, line_amount | 1 注文に 1 件以上。line_no は注文内で一意。 |
| order_status_histories | order_id, from_status, to_status, actor_user_id, comment, occurred_at | 状態変更を追加専用で記録する。 |

## 7. API 概要

| メソッド | パス | 権限 | 内容 |
| --- | --- | --- | --- |
| GET | `/api/orders` | 認証済み | 管理者は全件、担当社員は自分の注文、顧客は自社注文だけを検索する。 |
| POST | `/api/orders` | 管理者、担当社員 | 顧客に代わる下書き注文を登録する。担当社員は割当済み顧客だけを指定できる。 |
| GET | `/api/orders/{orderId}` | 権限保有者 | 注文詳細を取得する。 |
| PATCH | `/api/orders/{orderId}` | 管理者、作成者 | 下書き・差戻し注文を更新する。 |
| POST | `/api/orders/{orderId}/submit` | 管理者、作成者 | 必須チェック後に承認依頼する。 |
| POST | `/api/orders/{orderId}/cancel` | 管理者、作成者 | 取消理由とともに取消する。 |
