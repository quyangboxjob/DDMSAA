# 業務基本設計 — 注文管理

## 1. 目的と利用者

ADMIN は全注文を、EMPLOYEE は担当顧客の注文を作成・編集・申請・取消しできる。CUSTOMER は自社注文を閲覧するだけである。

## 2. 画面

画面設計は `spec-order-screen-ui.md`、画面 ID・パス・遷移は `../../共通/spec-05-screen-list-ui.md` を正とする。

| 画面 ID | 画面 | 主な利用者 | 内容 |
|---|---|---|---|
| SCR-11 | 注文一覧 | 全ロール | データ範囲に限定した検索・状態表示 |
| SCR-12 | 注文登録/編集 | ADMIN/EMPLOYEE | 顧客、担当者（ADMIN）、明細、数量、申請（単価は商品から複写） |
| SCR-13 | 注文詳細 | 全ロール | 金額、税、状態履歴、承認履歴、許可済み添付、取消し（SCR-13/DLG-1）、承認操作 |

## 3. 状態・権限

| 状態 | 編集 | 申請 | 取消し |
|---|---|---|---|
| DRAFT | ADMIN/担当EMPLOYEE | ○ | ○ |
| RETURNED | ADMIN/担当EMPLOYEE | ○ | ○ |
| PENDING_APPROVAL | × | × | × |
| APPROVED | × | × | ADMIN のみ（EMPLOYEE は 403） |
| CANCELLED | × | × | × |

## 4. 金額

- 明細の単価は商品の標準単価とし、画面から変更できない。DRAFT / RETURNED の保存のたびに商品のコード、名称、単価、税区分、税率を最新の値で複写し、申請時の値で確定する（BR-PRD-002）。
- 無効商品は明細に新しく追加できない。既存明細に残った無効商品・無効顧客・担当外の顧客があると申請できない（BR-PRD-003 / BR-ORD-010）。
- 明細金額は `quantity × unit_price`、税額は `HALF_UP(line_amount × tax_rate / 100)` とする。
- 税区分は STANDARD 10%、REDUCED 8%、EXEMPT 0%。値引き、送料、外貨は初版で扱わない。
- サーバーが明細から小計、税額、合計を再計算し、画面からの集計値は信用しない。

- 担当者は、EMPLOYEE が作成した注文は本人、ADMIN が作成した注文は顧客の有効な担当 EMPLOYEE から指定する（BR-ORD-008）。

## 5. 訂正と監査

承認済み注文は直接変更しない。取消し後、新規注文を作成して訂正する場合は `revised_from_order_id` に元注文（CANCELLED・同一顧客・訂正は 1 回）を記録できる（BR-ORD-009）。作成、更新、申請、承認、差戻し、取消しは監査ログに、状態遷移は状態履歴にも残す（BR-ORD-011）。
