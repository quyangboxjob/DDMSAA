# 業務基本設計 — ユーザー管理・認証

## 1. 権限

ADMIN だけがユーザーを登録、更新、停用・停用解除、ロック・ロック解除、ロール変更できる。ロールは ADMIN、EMPLOYEE、CUSTOMER の 3 種だけである（`../../共通/spec-03-auth-ui.md`）。

## 2. 管理項目

ユーザー ID、表示名、メールアドレス（`user_contacts`）、ロール、状態（有効/停用）、ロック（`system_locks`）、CUSTOMER の顧客紐付けを管理する。

- ユーザー ID は登録時にロールに応じて採番する（ADMIN=`A`、EMPLOYEE=`E`、CUSTOMER=`C` + 4 桁）。ロールを変更しても ID は変えない。
- パスワードは持たない。ログインはユーザー ID を入力し、登録メールアドレスに届く Magic Link で行う（`../../基盤/spec-02-auth-service-ui.md`）。
- Magic Link のトークンは画面・ログ・監査に残さない。

## 3. ログイン

1. 利用者がユーザー ID を入力すると、システムは利用者の状態を確認し、ログイン可能なら Magic Link を送信する。応答は可否に関わらず同一とする。
2. 利用者がメールのリンクを開くと、トークンを検証し（1 回限り・60 分有効）、利用者の状態を再確認したうえで JWT（60 分）を発行する。
3. JWT の期限切れ後は再度 Magic Link でログインする。ログアウトはブラウザ側でトークンを破棄する。

## 4. 停用・ロック

- 停用・ロック中の利用者はログインできない。ログイン済みの利用者は、発行済みの JWT の有効期限（最長 60 分）まで利用でき、その後は再ログインできない（即時の強制ログアウトは行わない）。
- 停用は `users.status`、ロックは `system_locks.lock_started_at` で管理する。パスワードがないため、ログイン試行回数によるロックは行わない。
- 既存注文・承認・監査の操作者情報は保持するため、利用者を物理削除しない。
