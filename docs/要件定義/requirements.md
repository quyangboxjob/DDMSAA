## 2. 背景・目的

DDMSAA は、商品、顧客、注文、承認、関連ファイルを一元管理する販売システムである。管理者、一般社員および顧客が同じ販売情報を、役割に応じた権限で利用する。

本システムは新規開発であり、現行システム分析および既存データ移行は初版の対象外とする。個人の表計算ファイルやメールだけで販売情報を管理する状態を避け、注文状況、承認状況および売上集計を追跡できる状態を実現する。

### 2.1 目標

1. 利用者の認証・権限に基づき、販売情報を安全に利用できる。
2. 商品、顧客、注文を一貫したデータとして管理できる。
3. 注文の承認・差戻しとその履歴を追跡できる。
4. 注文に関係する資料を添付して管理できる。
5. 検索、集計、帳票、メール通知により日常の販売業務を支援できる。

### 2.2 初版の対象外

- オンライン決済およびクレジットカード決済
- 会計、在庫、倉庫、配送会社との自動連携
- 既存システムからのデータ移行
- 多言語画面（初版の表示言語は日本語）

## 3. 利用者・役割・権限

| 役割 | 想定利用者 | 主な権限 |
| --- | --- | --- |
| システム管理者 | 業務責任者、IT 管理者 | 利用者、役割、商品、顧客、注文、承認ルール、帳票を管理する。全データを参照できる。 |
| 一般社員 | 営業担当、受注担当、承認担当 | 担当する顧客・注文を登録、参照、更新する。承認者に指定された注文を承認または差戻しする。 |
| 顧客 | 取引先担当者 | 自社の注文および注文に紐付く閲覧可能な添付資料を参照する。他社の情報は閲覧できない。注文の登録・更新・取消および添付資料の登録は行えない。 |

### 3.1 権限制御方針

- 未ログイン利用者は公開画面以外にアクセスできない。
- 顧客は、自身が所属する顧客に紐付く注文だけを閲覧できる。注文の登録・更新・取消はできない。
- 一般社員は、自分が担当する注文を更新できる。
- 管理者だけが、利用者・役割・商品マスタ・顧客マスタ・承認ルールを変更できる。
- 承認済み注文は直接変更できない。変更が必要な場合は、差戻しまたは改訂履歴として残す。

## 4. 業務フロー

```text
ログイン
  → 商品・顧客の選択
  → 注文登録（下書き）
  → 添付ファイル登録
  → 承認依頼
  → 承認または差戻し
  → 受注確定
  → 検索・帳票・売上集計
```

| 注文ステータス | 説明 | 主な操作 |
| --- | --- | --- |
| 下書き | 作成途中、未提出 | 作成者が編集、削除、承認依頼できる。 |
| 承認待ち | 承認者の判断待ち | 承認者が承認または差戻しする。 |
| 差戻し | 修正が必要 | 作成者が修正し、再度承認依頼する。 |
| 承認済み | 業務上有効な注文 | 原則として変更不可。帳票出力対象。 |
| 取消 | 取消済み | 履歴として参照のみ可能。 |

## 5. 機能要件

### FR-01 ログイン・ログアウト

1. 登録済みアカウントでログインできること。
2. ログイン後は、役割に応じたメニューとデータだけを表示すること。
3. 利用者は任意にログアウトできること。
4. 一定時間操作がない場合はセッションを失効し、再ログインを要求すること。
5. ログイン失敗を記録し、連続失敗時の不正利用対策を行うこと。

### FR-02 利用者・権限管理

1. 管理者は利用者を登録、編集、無効化できること。
2. 利用者に「管理者」「一般社員」「顧客」の役割を付与できること。
3. 顧客利用者は所属顧客を必須で持つこと。
4. 無効化された利用者はログインできないこと。
5. 権限変更および重要なアカウント操作は監査ログに記録すること。

### FR-03 商品管理

1. 管理者は商品を登録、編集、無効化できること。
2. 商品には商品コード、商品名、分類、単価、税区分、有効状態を保持すること。
3. 商品コードは重複登録できないこと。
4. 無効な商品は新規注文で選択できないこと。
5. 商品一覧を商品コード、商品名、分類、有効状態で検索できること。

### FR-04 顧客管理

1. 管理者は顧客を登録、編集、無効化できること。
2. 顧客には顧客コード、顧客名、所在地、連絡先、担当者、有効状態を保持すること。
3. 顧客コードは重複登録できないこと。
4. 無効な顧客は新規注文の対象として選択できないこと。
5. 顧客は自社の基本情報を参照できるが、重要項目の変更は管理者が行うこと。

### FR-05 注文管理

1. 一般社員は、新規注文を顧客に代わって下書きとして作成できること。顧客は注文を登録、更新、取消できないこと。
2. 注文には注文番号、注文日、顧客、担当社員、明細、数量、単価、税額、合計金額、ステータスを保持すること。
3. 注文明細は複数行登録でき、商品、数量、単価、金額を設定できること。
4. 合計金額および税額は、明細を基にシステムが計算すること。
5. 注文番号はシステムが一意に採番すること。
6. 下書きおよび差戻し状態の注文は、作成者が編集または削除できること。
7. 承認済み注文を変更する場合は、変更履歴または改訂注文として記録すること。
8. 注文一覧を注文番号、顧客、担当者、注文日、ステータス、金額で検索・絞り込みできること。

### FR-06 承認管理

1. 注文作成者は、必須入力が完了した注文について承認依頼できること。
2. 承認依頼時に、対象承認者へメール通知を送信できること。
3. 承認者は承認または差戻しを選択できること。
4. 差戻し時は理由を必須入力とすること。
5. 承認・差戻しの日時、実行者、コメントを履歴として保存すること。
6. 承認完了時は作成者へメール通知を送信できること。
7. 金額に応じた承認ルールを管理者が設定できること。金額閾値・段階数は別途決定する。

### FR-07 ファイル添付

1. 管理者または一般社員は、注文に見積書、注文書、仕様書などの関連ファイルを添付できること。顧客は添付ファイルを登録、更新、削除できないこと。
2. 添付ファイルには、ファイル名、種別、登録者、登録日時を記録すること。
3. 権限を持つ利用者だけが添付ファイルをダウンロードできること。
4. 実行形式ファイルなど、禁止された拡張子は添付できないこと。
5. 最大ファイルサイズ、許可拡張子、保存期間は運用ルールで定めること。

### FR-08 検索・照会

1. 利用者は権限の範囲で、商品、顧客、注文を検索できること。
2. 注文検索では、注文番号、顧客名、注文日範囲、ステータス、担当者、金額範囲を指定できること。
3. 一覧から詳細画面へ遷移し、明細、承認履歴、添付ファイルを確認できること。
4. 検索結果は並び替えおよびページングに対応すること。

### FR-09 帳票・報表

1. 承認済み注文について、注文書または注文確認書を出力できること。
2. 管理者および一般社員は、受注件数、受注金額、顧客別集計、商品別集計を確認できること。
3. 集計対象期間を指定できること。
4. 一覧・集計結果を CSV 形式で出力できること。
5. 帳票の正式レイアウトおよび PDF 出力の要否は別途決定する。

### FR-10 メール通知・監査ログ

1. 承認依頼、承認、差戻し、取消時にメールを送信できること。
2. メールには注文番号、対象顧客、実行内容、対象画面への案内を含めること。
3. メール送信失敗は再送可能な状態で履歴を残すこと。
4. ログイン、権限変更、商品・顧客・注文の登録/更新/削除、承認、添付ファイル操作を監査ログに記録すること。
5. 監査ログには実行者、日時、対象、操作種別、内容の要約を保存し、一般社員および顧客は変更できないこと。

## 6. データ要件

| データ | 主な項目 |
| --- | --- |
| 利用者 | 利用者ID、氏名、メール、役割、所属顧客、有効状態 |
| 顧客 | 顧客コード、名称、住所、連絡先、担当者、有効状態 |
| 商品 | 商品コード、名称、分類、単価、税区分、有効状態 |
| 注文 | 注文番号、顧客、担当者、注文日、ステータス、金額 |
| 注文明細 | 商品、数量、単価、金額、税額 |
| 承認履歴 | 注文、承認者、結果、コメント、日時 |
| 添付ファイル | 注文、ファイル名、保存先、種別、登録者、日時 |
| 通知履歴 | 宛先、通知種別、送信状態、送信日時 |
| 監査ログ | 実行者、対象、操作、日時、内容 |

## 7. 非機能要件

### 7.1 画面・操作性

- 画面、入力項目、エラーメッセージ、帳票の基本言語は日本語とする。
- PC ブラウザを基本とし、主要操作はスマートフォンでも利用できるレスポンシブ画面とする。
- Chrome および Edge の最新安定版を初期サポート対象とする。
- 入力エラーは、修正すべき項目と理由を画面上で分かるように表示する。

### 7.2 セキュリティ

- 通信は HTTPS を使用する。
- パスワードを平文で保存しない。
- URL を直接指定しても、権限のない利用者が他社または他者の情報を取得・更新できないこと。
- 添付ファイルは認可チェックを経由してアクセスすること。

### 7.3 性能・運用

- 通常の一覧検索および詳細表示は、標準的な業務ネットワーク環境で概ね 3 秒以内の応答を目標とする。
- 大量データの帳票・CSV 出力は、非同期処理または進捗表示を検討する。
- データベースは定期バックアップを取得し、復元手順を運用文書として整備する。
- アプリケーションエラーおよびメール送信失敗を運用者が確認できるログを残す。

## 8. 受入基準

| ID | 受入基準 |
| --- | --- |
| AC-01 | 管理者、一般社員、顧客がログインでき、役割に応じた画面だけを利用できる。 |
| AC-02 | 管理者が商品・顧客・利用者を登録し、無効化した情報が新規注文で選択できない。 |
| AC-03 | 一般社員が顧客に代わって複数明細を持つ注文を作成し、金額が正しく計算される。顧客は注文を作成、更新、取消できない。 |
| AC-04 | 注文を承認依頼し、承認者が承認または理由付きで差戻しでき、履歴が残る。 |
| AC-05 | 顧客が他社の注文・添付ファイルへアクセスできず、自社の注文についても閲覧以外の操作を行えない。 |
| AC-06 | 許可された形式のファイルを添付、閲覧、ダウンロードできる。 |
| AC-07 | 条件指定により注文を検索し、CSV 形式で出力できる。 |
| AC-08 | 承認依頼、承認、差戻し時のメール通知が記録される。 |
| AC-09 | 主要な業務操作が監査ログで確認できる。 |

2. 消費税計算、端数処理、値引き・送料の扱い。
3. 注文書・帳票の正式レイアウト、PDF 出力の要否。
4. 添付可能な拡張子、最大サイズ、保存期間、ウイルススキャン方式。
5. メールサービス、差出人アドレス、通知文面。
6. 同時利用者数、年間注文件数、データ保管期間。
7. 在庫、出荷、請求、会計、決済を初版に含めるか。
