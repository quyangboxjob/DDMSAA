## 1. 目的

販売担当者が顧客の注文を代行登録し、管理者が承認し、顧客が自社注文と公開済み添付を確認できる販売システムを提供する。商品、顧客、注文、承認、添付、集計、メール通知、監査記録を一つのシステムで扱う。

## 2. 利用者と権限

| ロール | できること | できないこと |
|---|---|---|
| ADMIN | 全データの管理、承認、監査、帳票、承認経路の設定、利用者の停用・ロック・解除 | — |
| EMPLOYEE | 担当顧客の注文作成・編集・申請、添付管理、担当範囲の参照・帳票 | 担当外顧客の操作、承認、マスタ管理 |
| CUSTOMER | 自社の注文、承認結果、顧客公開かつ安全な添付、PDF の参照 | 注文作成/更新/取消し、承認、添付操作、CSV、マスタ管理 |

- ロールはこの 3 種に固定する。DB では INT のコード値（ADMIN=1、EMPLOYEE=2、CUSTOMER=3）、API・JWT ではロール名の文字列で扱う。
- 認証は**パスワードレス**とする。利用者はユーザー ID を入力し、登録メールアドレスに届く Magic Link（1 回限り・有効 60 分）でログインする。パスワードは保存も入力もしない。

## 3. 機能要件

| ID | 機能 | 要件 |
|---|---|---|
| FR-01 | ログイン | ユーザー ID による Magic Link の送信・再送、Magic Link 検証によるログイン、ログアウト、自分の情報表示を提供する |
| FR-02 | ユーザー管理 | ADMIN が利用者、ロール、連絡先メール、停用、ロック/解除、顧客紐付けを管理する |
| FR-03 | 商品管理 | ADMIN が商品コード、名称、価格、税区分、有効状態を管理する |
| FR-04 | 顧客管理 | ADMIN が顧客、連絡先、担当社員を管理する |
| FR-05 | 注文管理 | ADMIN/担当 EMPLOYEE が注文・明細を作成、編集、申請、取消しできる。サーバーが金額・税額・合計を再計算する |
| FR-06 | 承認 | 申請後、ADMIN が承認又は理由付き差戻しを行う。経路と操作履歴を保存し通知する |
| FR-07 | 添付 | ADMIN/担当 EMPLOYEE が注文添付を操作する。顧客は公開・安全な自社添付だけを参照できる |
| FR-08 | 検索/監査 | 注文を条件検索し、重要操作を監査ログに記録する |
| FR-09 | 帳票/集計 | 注文 PDF、集計画面、CSV 出力を権限・データ範囲に応じて提供する |
| FR-10 | 通知 | Magic Link、承認申請、承認、差戻し、取消し、出力完了をメール通知し、業務通知は送信履歴を記録する |

## 4. 注文状態

    DRAFT -> PENDING_APPROVAL: 申請
    RETURNED -> PENDING_APPROVAL: 再申請
    PENDING_APPROVAL -> APPROVED: ADMIN 承認
    PENDING_APPROVAL -> RETURNED: ADMIN 差戻し
    DRAFT/RETURNED -> CANCELLED: 取消し
    APPROVED -> CANCELLED: ADMIN 取消し

- `DRAFT` と `RETURNED` だけを編集・申請できる。
- `APPROVED` は直接編集できない。訂正は取消し後に新規注文を作成し、必要なら元注文を `revised_from_order_id` に記録する。
- すべての遷移は状態履歴と監査ログに残す。

## 5. 初版で確定した業務ルール

### 5.1 税額と金額

- 税区分は `STANDARD=10%`、`REDUCED=8%`、`EXEMPT=0%` とする。
- 明細金額は `quantity × unit_price`、明細税額は `HALF_UP(line_amount × tax_rate / 100)` として明細ごとに計算する。
- 明細の単価は商品の標準単価をサーバーで複写し、画面から変更できない。
- 注文小計、税額、合計は明細からサーバーで再計算して保存する。画面から送られた合計値を信用しない。
- 初版では値引き、送料、外貨、複数通貨を扱わない。

### 5.2 承認

- 初版の経路は、金額を問わず `ADMIN` による 1 段承認とする。
- 申請時点の経路を `approval_requests.rule_snapshot` に複写し、後から経路設定を変えても申請済み注文には遡及しない。
- 承認者は特定せず、有効な `ADMIN` のうち申請者本人以外が承認・差戻しできる。申請者本人は自分の注文を承認できない。
- 代理承認・多段承認は初版の対象外とする。

### 5.3 添付

- 許可する拡張子/MIME は PDF、DOCX、XLSX、CSV、PNG、JPG/JPEG。
- 1 ファイルは 10 MiB 以下、注文あたり合計 50 MiB 以下。
- 保存後は `PENDING` とし、スキャン結果が `SAFE` になるまでダウンロードできない。`REJECTED` は配信しない。
- 顧客表示は `CUSTOMER` 公開を明示したファイルだけに限る。保持期間はアップロードから 365 日とする。

### 5.4 帳票・CSV

- 注文 PDF は `APPROVED` の注文だけを対象とし、A4 の日本語レイアウトで、注文番号、顧客、明細、税額、合計、状態を表示する。
- CSV は UTF-8 BOM とし、CUSTOMER には提供しない。
- すべての CSV 出力を `export_jobs` に記録する。10,000 件以下は同期生成、10,001 件以上は非同期で生成し、成果物は 24 時間で失効する。

### 5.5 認証・ログイン

- ログインはユーザー ID を入力して Magic Link を要求し、メールのリンクを開いて完了する。Magic Link は 1 回使用で失効し、有効期限は 60 分、再送回数に上限はない。
- Magic Link の送信先は利用者の登録メールアドレス（連絡先）とする。
- Magic Link 要求の応答は、利用者の存在・停用・ロックに関わらず同一とし、アカウントの有無を開示しない。
- ログイン後は JWT アクセストークン（有効 60 分、リフレッシュなし）で API を利用する。期限切れ時は再度 Magic Link でログインする。
- ADMIN は利用者を停用・ロック・ロック解除できる。停用中・ロック中の利用者はログインできない。ログイン済みの利用者は、発行済みの JWT の有効期限（最長 60 分）まで利用を続けられる。
- パスワード、パスワード変更、パスワード試行回数によるロックは存在しない。

## 6. 非機能要件

- 本番は HTTPS とする。API は `Authorization: Bearer` の JWT で認証し、Cookie セッションと CSRF トークンは使用しない。
- PC の Chrome / Edge 最新版を対象とし、日本語 UI とする。メッセージカタログは日本語・中国語・英語を持つ。
- 通常検索 API は 95 パーセンタイル 2 秒以内を目標にする。
- DB は日次バックアップし、四半期ごとに復元試験を行う。
- ログイン、権限拒否、状態変更、添付、帳票、出力を監査する。
- システム方式（API Gateway、認証サービス、業務サービスの構成）、API 規約、DB 規約は基盤基本設計と開発規約に従う（`基本設計/基盤/spec-00-architecture-ui.md`、`開発規約/spec-database-rule.md`）。

## 7. 受入基準

1. ADMIN/EMPLOYEE/CUSTOMER のデータ範囲が API で強制される。
2. EMPLOYEE は担当顧客にだけ注文を作成・変更できる。
3. CUSTOMER は自社注文を表示できるが、注文作成・更新・取消しはできない。
4. 注文申請時に税額と合計がサーバーで再計算され、ADMIN の承認/差戻しが履歴付きで実行できる。
5. SAFE かつ CUSTOMER 公開の添付だけを顧客がダウンロードできる。
6. 権限に応じた PDF/CSV が作成され、大量 CSV は非同期ジョブとして扱われる。
7. ユーザー ID と Magic Link でログインでき、停用・ロック中の利用者はログインできない。応答から利用者の存在は判別できない。
