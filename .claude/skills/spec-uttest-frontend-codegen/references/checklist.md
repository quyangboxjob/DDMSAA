# フロントエンド単体テスト生成後チェック門（G-*）

1つでも不合格ならテストコードを直す（実装コード側は直さない。実装のバグらしきものを見つけた場合は、直さずにユーザーへ報告する）。

- **G-1 実行できる**: テストコマンドが成功し、ログの`Tests`行が実際に書いたテスト数と一致する。
- **G-2 環境設定が規約どおり**: 実行環境は `jsdom`（`docs/開発規約/spec-test-rule.md` §7、2026-10-21 決定）。jsdomの一部バージョンには全テストが起動不能になる既知の問題があるため、バージョンを固定し、変更時は全テストが起動することを確認する。
- **G-3 配置・命名が規約通り**: 対象ファイルと同じディレクトリの`__tests__/`配下、ファイル名は`<対象ファイル名>.test.ts`（コンポーネントは`.test.tsx`）。
- **G-4 クエリの選び方が適切**: 「無いことの確認」に`getByText`を使っていない（`queryByText`を使う）。DOM構造への依存が強い`container.querySelector`を安易に使っていない（`getByRole`/`getByText`等のユーザー視点のクエリを優先）。
- **G-5 アサーションが意味を持つ**: 「レンダリングが例外を投げない」だけの確認に終わっていない。表示内容・返り値など具体的な期待値を検証している。
- **G-6 境界値をカバーしている**: 空文字/undefined/未知の値など、実装コードの分岐に対応する境界がテストされている。
- **G-7 外部依存の要否を見極めている**: Context・i18n・ルーター等に依存するコードをテストする場合、モックが必要以上に肥大化していないか（肥大化する場合はテスト対象の粒度を見直す＝ロジックをpropsだけで完結する純粋関数/コンポーネントに切り出せないか検討する）。**Context自体は`vi.mock(...)`で差し替えず、`renderHook`/`render`の`wrapper`でテスト用の`Provider`をかぶせている**（本プロジェクトはzustand等の外部storeを使わない）。
- **G-8 モジュールトップレベルの状態リークが無い**: Contextを介さない共有状態（モジュールスコープのシングルトン等）に依存するテストがある場合、`beforeEach`で既知の初期値にリセットしている。
- **G-9 コールバック検証が具体的**: クリック等のユーザー操作を伴うテストで、`vi.fn()`のコールバックが「呼ばれたか」だけでなく`toHaveBeenCalledWith(...)`で引数まで検証している。
- **G-10 結果判定レポートを出力している**: `単体テスト/フロントエンド/report/spec-ut-fe-testreport-<date>.md`を出力し、データ源がvitest junit reporterのXMLであり、`Test Files`/`Tests`行の実数と一致している（失敗/スキップがあれば隠さず記載）。
