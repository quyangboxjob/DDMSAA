# チェック門（G-\*）— 単体テスト仕様書（フロントエンド）

作成・更新した単体テスト仕様書に対し、以下を全て確認する。1つでも不合格なら仕様書を見直す。

- **G-1 対象外の明記**: 画面本体等、対象外と判断したものは省略せず「対象外とする理由」が1文で明記されている（洗い出し漏れとの区別がつく）。
- **G-2 実装状況の正確性**: `実装済み`と記載した行は、実在するテストファイル・テストケース名を`Glob`/`Grep`で実際に確認した上で記載している（推測で「実装済み」にしない）。
- **G-3 費用対効果方針との整合**: 純粋関数・カスタムフック・プレゼンテーショナルコンポーネントを優先し、画面本体の網羅を無理に求めていない。zustand等の外部store前提の項目（`setState`直接操作等）を紛れ込ませていない（本プロジェクトはContext＋ローカルstate）。
- **G-4 将来候補の実現可能性**: 「`export`すれば切り出せる」候補を挙げる場合、対象関数が実際にモジュール内に定義されていることを確認している（存在しない関数を挙げない）。
- **G-5 i18n非依存の検証**: 表示内容を検証する項目は、日本語文言の直接比較ではなくi18nキー/`t()`呼び出し引数で書かれている（三語対応のため）。
- **G-6 配置・命名**: `単体テスト/フロントエンド/spec-<domain/ファイル名kebab-case>-unittest-sd.md`に配置されている（リポジトリルート直下`単体テスト/`）。
